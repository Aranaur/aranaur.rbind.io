Що ми робимо сьогодні

На лекції ми побачили головну формулу планування A/B: розмір групи \(n \propto \sigma^2 / \Delta^2\). Ефект \(\Delta\) диктує економіка, трафік \(n\) обмежений часом — і лишається єдиний вільний важіль: \(\sigma\). Сьогодні збираємо власноруч інструменти, що зменшують дисперсію метрики, не чіпаючи ані даних, ані чесності критерію: ту саму вибірку робимо чутливішою.

  • strat_ttest — стратифікація за відомою структурою аудиторії;
  • calculate_theta + cuped — коригування метрики передекспериментальною історією користувача;
  • linearize — правильна одиниця аналізу для ratio-метрик;
  • vr_ci — компонуємо все в один критерій і валідуємо Монте-Карло;
  • vr_report — фінал: наскільки менше користувачів треба та яке бізнес-рішення це дає.
ПриміткаПравила гри
  • Наскрізний кейс: GreenBowl (той самий, що в Практиках 4–9) запускає email-кампанію з персональним промо-набором. Головна метрика — ARPU за 2 тижні; наприкінці зачепимо й конверсію сесій.
  • Будуємо один інструмент поступово: кожна частина додає одну нову здатність — від strat_ttest до фінального vr_report.
  • Дані генеруємо самі (greenbowl_users) — знаємо «правду» і можемо перевіряти чесність кожної версії Монте-Карло (звичка з Практики 5).
  • Перед кожним результатом — 🔮 «Спершу вгадайте»: запишіть відповідь до запуску коду. Після — «Ваша черга» зі згорнутим розв’язанням.
  • Дизайн ≠ рішення: design-MDE — для розрахунку \(n\) до запуску; breakeven — поріг рішення після. Пост-хок потужності у звіті немає.
alpha = 0.05
z_a, z_b = norm.ppf(1 - alpha/2), norm.ppf(1 - 0.20)

def n_per_arm(sd, delta):
    """Розмір групи для двовибіркового t-тесту (потужність 80%, alpha 5%)."""
    return int(np.ceil((z_a + z_b)**2 * 2 * sd**2 / delta**2))

sigma, mde = 80.0, 10.0                 # історичне sd ARPU; breakeven-ефект
print(f"базовий дизайн: sd = {sigma:.0f}, MDE = {mde:.0f} грн "
      f"-> {n_per_arm(sigma, mde)} користувачів на групу")
базовий дизайн: sd = 80, MDE = 10 грн -> 1005 користувачів на групу

1 Частина I — Стратифікація

Кейс. GreenBowl має програму лояльності. З історії: зареєстровані користувачі витрачають у середньому 300 грн за 2 тижні, незареєстровані — 200 грн, у кожної підгрупи \(sd \approx 62\), частки \(50/50\). Звичайний t-тест бачить один розмазаний розподіл зі \(\sigma \approx 80\) — і платить за це розміром вибірки.

mu_bar   = 0.5*MU_R + 0.5*MU_U
var_in   = SD_W**2
var_betw = 0.5*(MU_R - mu_bar)**2 + 0.5*(MU_U - mu_bar)**2
print(f"дисперсія всередині страт: {var_in:.0f}  (sd {np.sqrt(var_in):.1f})")
print(f"дисперсія МІЖ стратами:    {var_betw:.0f}  (sd {np.sqrt(var_betw):.1f})")
print(f"повна дисперсія:           {var_in+var_betw:.0f}  "
      f"(sd {np.sqrt(var_in+var_betw):.1f})")
print(f"частка 'між' у дисперсії:  {var_betw/(var_in+var_betw):.0%}")
дисперсія всередині страт: 3844  (sd 62.0)
дисперсія МІЖ стратами:    2500  (sd 50.0)
повна дисперсія:           6344  (sd 79.6)

39% дисперсії, з якою бореться t-тест, — це різниця між стратами. Але статус лояльності ми знаємо до експерименту: платити за цю частину розміром вибірки — марно. Стратифікація «відрізає» доданок між і лишає тесту лише справжній шум усередині.

Порада🔮 Спершу вгадайте

Стратифіковане середнє — це зважена сума середніх по стратах з популяційними вагами \(w_s\): \(\hat{Y}_{str} = \sum_s w_s \bar{Y}_s\). Його дисперсія \(\sum_s w_s^2 \sigma_s^2 / n_s\) не містить доданка «між». На скільки, по-вашому, зросте потужність, якщо ефективне \(sd\) впаде з 80 до 62?

1.1 Інструмент v1: strat_ttest

def strat_ttest(stratum_c, y_c, stratum_t, y_t, w=(0.5, 0.5)):
    """Двовибірковий t-тест на стратифікованих середніх.

    w — популяційні частки страт (незареєстровані, зареєстровані).
    Повертає двосторонній p-value.
    """
    means, vars = [], []
    for reg, y in ((stratum_c, y_c), (stratum_t, y_t)):
        groups = [y[~reg], y[reg]]                       # [незареєстр., зареєстр.]
        means.append(sum(wi * g.mean() for wi, g in zip(w, groups)))
        vars.append(sum(wi**2 * g.var(ddof=1) / g.size for wi, g in zip(w, groups)))
    t = (means[1] - means[0]) / np.sqrt(vars[0] + vars[1])
    return 2 * tdist.sf(abs(t), y_c.size + y_t.size - 2)

Валідуємо, як завжди, Монте-Карло: генеруємо A/A-світи (без ефекту → маємо бачити FPR \(\approx \alpha\)) і A/B-світи (ефект +10 грн → потужність), для звичайного і стратифікованого тестів на тих самих даних.

rng, MC = np.random.default_rng(11), 400
n = n_per_arm(sigma, mde)               # 1005
cnt = dict.fromkeys(["plain FPR", "plain power", "strat FPR", "strat power"], 0)

for _ in range(MC):
    a  = greenbowl_users(n, rng)
    b  = greenbowl_users(n, rng)
    t_ = greenbowl_users(n, rng, uplift=mde)
    cnt["plain FPR"]   += ttest_ind(a["arpu"], b["arpu"],  equal_var=False).pvalue < alpha
    cnt["plain power"] += ttest_ind(a["arpu"], t_["arpu"], equal_var=False).pvalue < alpha
    cnt["strat FPR"]   += strat_ttest(a["stratum"], a["arpu"], b["stratum"], b["arpu"]) < alpha
    cnt["strat power"] += strat_ttest(a["stratum"], a["arpu"], t_["stratum"], t_["arpu"]) < alpha

for k, v in cnt.items():
    print(f"{k:12s}: {wilson(v, MC)}")

2 Частина II — CUPED

Кейс. Стратифікація використала грубу мітку. Але в нас є значно багатше знання — власна історія кожного користувача: скільки він витрачав до експерименту (pre). Використаймо її, щоб порівнювати кожного з його ж минулим.

CUPED (Controlled-experiment Using Pre-Experiment Data) коригує метрику \(Y\) передекспериментальною коваріатою \(X\):

\[ Y_{cuped} = Y - \theta X, \qquad \theta = \frac{\operatorname{Cov}(X, Y)}{\operatorname{Var}(X)}, \qquad \operatorname{Var}(Y_{cuped}) = \operatorname{Var}(Y)\,(1 - r^2). \]

\(\theta\) — спільна для обох груп константа, тож завдяки рандомізації різниця середніх лишається незміщеною: ми не рухаємо оцінку ефекту, лише прибираємо з неї передбачувану частину шуму.

Порада🔮 Спершу вгадайте

Виграш CUPED — це рівно \(1 - r^2\). У нашому світі pre корелює з arpu всередині страти на \(0.7\). Але pre ще й «знає» страту (зареєстровані більші і за pre, і за arpu). Якою буде повна кореляція pre з arpu — рівно \(0.7\) чи більше? І яким тоді буде відношення дисперсій?

2.1 Інструмент v2: calculate_theta + cuped

def calculate_theta(x, y):
    return np.cov(x, y)[0, 1] / x.var(ddof=1)

def cuped(y, x, theta):
    return y - theta * x
rng = np.random.default_rng(0)
a = greenbowl_users(200_000, rng)                    # велика когорта для оцінки r
r_full = np.corrcoef(a["pre"], a["arpu"])[0, 1]
theta  = calculate_theta(a["pre"], a["arpu"])
vr     = cuped(a["arpu"], a["pre"], theta).var() / a["arpu"].var()
print(f"повна кореляція r(pre, arpu): {r_full:.3f}")
print(f"1 - r^2:                      {1 - r_full**2:.3f}")
print(f"виміряне відношення дисперсій: {vr:.3f}")
повна кореляція r(pre, arpu): 0.818
1 - r^2:                      0.331
виміряне відношення дисперсій: 0.331

Кореляція виявилась \(\approx 0.82\), а не \(0.7\): pre несе в собі і внутрішньостратову історію, і саму страту. Тому CUPED сам по собі зрізає \(\approx 67\%\) дисперсії — більше, ніж стратифікація. Запам’ятаймо цей факт: у Розділ 4 він пояснить, чому «стратифікація + CUPED» майже не додає понад самий CUPED.

ПриміткаРозв’язання 2 
def make_cov(y, r, rng):
    """Коваріата із заданою ПОВНОЮ кореляцією r до y."""
    zy = (y - y.mean()) / y.std()
    return r * zy + np.sqrt(1 - r**2) * rng.standard_normal(y.size)

rng_c = np.random.default_rng(3)
a = greenbowl_users(200_000, rng_c)
for r in (0.2, 0.5, 0.7):
    x = make_cov(a["arpu"], r, rng_c)
    th = calculate_theta(x, a["arpu"])
    ratio = cuped(a["arpu"], x, th).var() / a["arpu"].var()
    print(f"(1) r = {r}: відношення дисперсій {ratio:.3f}  (1 - r^2 = {1 - r**2:.2f})")

(1) r = 0.5: відношення дисперсій 0.752  (1 - r^2 = 0.75)

Інтерпретація. (1) Закон тримається точно: \(r=0.2 \to 0.96\) (зрізали лише 4% — не вартує пайплайна), \(r=0.5 \to 0.75\), \(r=0.7 \to 0.51\). Мінімум здорового глузду — \(|r| \gtrsim 0.3\). (2) Для новачків підставляємо \(X = \bar X\) (середнє коваріати): тоді \(Y_{cuped} = Y - \theta \bar X\) — вони просто не отримують коригування, а незміщеність зберігається, бо константа однакова в обох групах. У Netflix новачки дають 5–15% зниження дисперсії проти 40% у старих саме через брак історії.

ВажливоОбережно: коваріата має бути «до» трітменту

CUPED і стратифікація безпечні лише на передекспериментальних ознаках. Коваріата, виміряна під час експерименту (сесії, візити), може ввібрати частину ефекту — і тихо змістити оцінку. Правило просте: усе, що зафіксовано до старту, — можна; усе, на що міг вплинути трітмент, — ні.

3 Частина III — Ratio-метрики та лінеаризація

Кейс. Продукт-менеджер просить іншу метрику: конверсію сесії в замовлення — «з усіх сесій скільки закінчились покупкою?». Спокуса — розгорнути кожну сесію в \(0/1\) і порівняти дві частки z-тестом. Але рандомізували ми користувачів, а рахуємо по сесіях.

ПопередженняСпіймай помилку 🕵️

GreenBowl запустив A/A-тест конверсії (ефекту немає). Два аналітики сперечаються, як рахувати.

def pooled_session_pvalue(sessions_c, orders_c, sessions_t, orders_t):
    """t-тест на розгорнутих 0/1 по СЕСІЯХ (аналіз Аналітика А)."""
    out = []
    for sess, ordr in ((sessions_c, orders_c), (sessions_t, orders_t)):
        ns, k = sess.sum(), ordr.sum()
        mean  = k / ns
        var   = (k*(1 - mean)**2 + (ns - k)*mean**2) / (ns - 1)
        out.append((mean, var, ns))
    (m1, v1, n1), (m2, v2, n2) = out
    t = (m2 - m1) / np.sqrt(v1/n1 + v2/n2)
    return 2 * tdist.sf(abs(t), n1 + n2 - 2)

rng, MC_r = np.random.default_rng(7), 300
fpr_pool = 0
for _ in range(MC_r):
    a = greenbowl_users(2000, rng)
    b = greenbowl_users(2000, rng)
    fpr_pool += pooled_session_pvalue(a["sessions"], a["orders"],
                                      b["sessions"], b["orders"]) < alpha
print(f"A/A FPR (пул сесій): {wilson(fpr_pool, MC_r)}")
A/A FPR (пул сесій): 0.457  Уілсон (0.401, 0.513)

Аналітик А: «Десятки тисяч сесій, крихітні похибки — беремо z-тест часток, і хай живе велике \(n\).»

Аналітик Б: «Сесії одного користувача не i.i.d.: у кожного своя схильність купувати. Ефективна одиниця — користувач, а не сесія. Дивись: на чистому A/A пул-тест відхиляє нуль у половині випадків — це машина з ухвалення плацебо-фіч.»

Хто має рацію? Аналітик Б: FPR \(\approx 0.5\) замість \(0.05\). Сесії множать обсяг даних, а не докази — одиниця аналізу має збігатися з одиницею рандомізації.

Чесна метрика групи — ratio \(K = \sum \text{orders} / \sum \text{sessions}\) (користувачі лишаються цілими). На лекції ми будували для неї ДІ бутстрепом по користувачах; сьогодні — швидша алгебра, лінеаризація: перетворити пару \((O_i, M_i)\) на одне по-користувацьке число \(Z_i\), до якого застосовний звичайний t-тест.

3.1 Інструмент v3: linearize

\[ Z_i = K + \frac{1}{\overline{O}}\big(M_i - K\,O_i\big), \qquad K = \frac{\overline{M}}{\overline{O}} \]

def linearize(num, den):
    """По-користувацька лінеаризована ratio-метрика (дельта-метод).

    num = замовлення (чисельник), den = сесії (знаменник).
    """
    k = num.sum() / den.sum()
    return k + (num - k * den) / den.mean()
rng = np.random.default_rng(1)
a = greenbowl_users(5000, rng)
z = linearize(a["orders"], a["sessions"])
print(f"K       = {a['orders'].sum()/a['sessions'].sum():.5f}")
print(f"mean(Z) = {z.mean():.5f}   <- відтворює K точно")
K       = 0.19992
mean(Z) = 0.19992   <- відтворює K точно

mean(Z) дорівнює \(K\) точно, тож t-тест по \(Z\) порівнює саме ту величину, про яку питає PM. Перевіримо чесність і потужність:

Інтерпретація. (1) Окремо тестуємо знаменник — середню кількість сесій на користувача — звичайним t-тестом (сесії на користувача — це i.i.d. по користувачах). Якщо знаменник зрушився, читати ratio наосліп не можна: у звіті ratio ніколи не ходить сама — чисельник, знаменник, відношення. Правило: не впевнені, що трітмент не чіпає знаменник, — тестуйте його окремо. (2) \(Z\)-минулого — легітимна передекспериментальна коваріата, не залежна від трітменту, тож CUPED на ній зменшить дисперсію конверсії так само, як для ARPU. Саме так методи компонуються — до цього в Розділ 4.

4 Частина IV — Все компонується + Монте-Карло

Лінеаризована \(Z\), стратифікація і CUPED — це все операції над по-користувацькою колонкою, тож вони стекаються. Зберемо CUPED + стратифікацію в один критерій vr_ci, що повертає варіанс-редукований ДІ для різниці ARPU.

def vr_ci(control, test, stratum_c=None, stratum_t=None,
          cov_c=None, cov_t=None, alpha=0.05):
    """Варіанс-редукований ДІ для різниці середніх test - control.

    Спершу CUPED (якщо задано коваріату), потім стратифіковане/звичайне
    середнє. Повертає (diff, (lo, hi), se).
    """
    yc, yt = np.asarray(control, float), np.asarray(test, float)
    if cov_c is not None:                                    # крок CUPED
        th = calculate_theta(np.r_[cov_c, cov_t], np.r_[yc, yt])
        yc, yt = yc - th*cov_c, yt - th*cov_t

    def mean_var(reg, y):
        if reg is None:
            return y.mean(), y.var(ddof=1) / y.size
        w, g = (0.5, 0.5), [y[~reg], y[reg]]                 # крок стратифікації
        m = sum(wi*x.mean() for wi, x in zip(w, g))
        v = sum(wi**2 * x.var(ddof=1)/x.size for wi, x in zip(w, g))
        return m, v

    mc, vc = mean_var(stratum_c, yc)
    mt, vt = mean_var(stratum_t, yt)
    diff, se = mt - mc, np.sqrt(vc + vt)
    z = norm.ppf(1 - alpha/2)
    return diff, (diff - z*se, diff + z*se), se
Порада🔮 Спершу вгадайте

Порядок методів за потужністю зрозумілий: plain < strat < cuped. А strat + CUPED — помітно кращий за самий CUPED чи майже такий самий?

def strat_cuped_p(sc, xc, yc, st, xt, yt):
    th = calculate_theta(np.r_[xc, xt], np.r_[yc, yt])
    return strat_ttest(sc, yc - th*xc, st, yt - th*xt)

5 Частина V — Фінал: vr_report

Кейс. Київський A/B email-кампанії завершено: по 1005 користувачів у групі. Субсидія промо-набору коштує 6 грн на користувача — це breakeven: фіча окупна, лише якщо піднімає ARPU більш ніж на 6 грн. CFO чекає рішення.

BASE, PERIODS = 80_000, 26              # київська база; 2-тижневих періодів на рік

def vr_report(control, test, breakeven, stratum_c=None, stratum_t=None,
              cov_c=None, cov_t=None, base=BASE, periods=PERIODS):
    """Фінальний звіт: варіанс-редукований ефект, тризонне рішення, P(окупно), EV."""
    diff, (lo, hi), se = vr_ci(control, test, stratum_c, stratum_t, cov_c, cov_t)
    zone = ("SHIP — котимо"          if lo > breakeven else
            "KILL — вимикаємо"       if hi < breakeven else
            "СІРА ЗОНА — треба даних")
    p_be = norm.sf((breakeven - diff) / se)          # P(ефект >= breakeven)
    ev   = base * periods * (diff - breakeven)        # очікувана чиста цінність за рік
    print(f"ефект ARPU:  {diff:+.2f} грн   95% ДІ ({lo:+.2f}, {hi:+.2f})")
    print(f"ефективне SE: {se:.2f} грн   breakeven {breakeven:+.0f} грн")
    print(f"рішення:     {zone}")
    print(f"P(окупно):   {p_be:.0%}")
    print(f"EV за рік:   {ev/1e6:+.1f} млн грн")
    return {"diff": diff, "ci": (lo, hi), "zone": zone, "p": p_be, "ev": ev}
