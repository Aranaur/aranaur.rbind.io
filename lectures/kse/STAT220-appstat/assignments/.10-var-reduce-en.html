What we do today

In the lecture we met the master A/B design formula: sample size \(n \propto \sigma^2 / \Delta^2\). The effect \(\Delta\) is dictated by economics, traffic \(n\) is capped by time — leaving one free lever: \(\sigma\). Today we build, by hand, the tools that reduce the variance of a metric without touching the data or the honesty of the test: the same sample, made more sensitive.

  • strat_ttest — stratification by known audience structure;
  • calculate_theta + cuped — adjust the metric with the user’s pre-experiment history;
  • linearize — the right unit of analysis for ratio metrics;
  • vr_ci — compose everything into one criterion and validate it with Monte Carlo;
  • vr_report — the finale: how many fewer users we need, and what business decision follows.
NoteRules of the game
  • Running case: GreenBowl (the same as in Practices 4–9) launches an email campaign with a personalised promo bundle. Primary metric — 2-week ARPU; at the end we touch session conversion too.
  • Build one tool progressively: each part adds one new capability — from strat_ttest to the final vr_report.
  • We generate the data ourselves (greenbowl_users) — we know the “truth” and can check each version’s honesty by Monte Carlo (the habit from Practice 5).
  • Before each result — 🔮 “Guess first”: write your answer before running the code. After it — “Your turn” with a collapsible solution.
  • Design ≠ decision: design-MDE sizes \(n\) before launch; breakeven is the decision threshold after. No post-hoc power in the report.
alpha = 0.05
z_a, z_b = norm.ppf(1 - alpha/2), norm.ppf(1 - 0.20)

def n_per_arm(sd, delta):
    """Sample size per arm for a two-sample t-test (80% power, alpha 5%)."""
    return int(np.ceil((z_a + z_b)**2 * 2 * sd**2 / delta**2))

sigma, mde = 80.0, 10.0                 # historical ARPU sd; breakeven effect

1 Part I — Stratification

Case. GreenBowl runs a loyalty program. From history: registered users spend on average 300 UAH over 2 weeks, unregistered 200 UAH, each subgroup with \(sd \approx 62\), shares \(50/50\). A plain t-test sees one smeared distribution with \(\sigma \approx 80\) — and pays for it in sample size.

mu_bar   = 0.5*MU_R + 0.5*MU_U
var_in   = SD_W**2
var_betw = 0.5*(MU_R - mu_bar)**2 + 0.5*(MU_U - mu_bar)**2
print(f"within-strata variance:  {var_in:.0f}  (sd {np.sqrt(var_in):.1f})")
print(f"BETWEEN-strata variance: {var_betw:.0f}  (sd {np.sqrt(var_betw):.1f})")

      f"(sd {np.sqrt(var_in+var_betw):.1f})")
print(f"between share:           {var_betw/(var_in+var_betw):.0%}")
within-strata variance:  3844  (sd 62.0)
BETWEEN-strata variance: 2500  (sd 50.0)
total variance:          6344  (sd 79.6)

39% of the variance the t-test fights is the difference between strata. But we know the loyalty status before the experiment: paying for that part in sample size is a waste. Stratification “cuts off” the between term and leaves the test only the genuine within noise.

Tip🔮 Guess first

The stratified mean is a weighted sum of stratum means with population weights \(w_s\): \(\hat{Y}_{str} = \sum_s w_s \bar{Y}_s\). Its variance \(\sum_s w_s^2 \sigma_s^2 / n_s\) has no between term. By how much do you think power rises if the effective \(sd\) drops from 80 to 62?

1.1 Tool v1: strat_ttest

def strat_ttest(stratum_c, y_c, stratum_t, y_t, w=(0.5, 0.5)):
    """Two-sample t-test on stratified means.

    w — population shares of the strata (unregistered, registered).
    Returns a two-sided p-value.
    """
    means, vars = [], []
    for reg, y in ((stratum_c, y_c), (stratum_t, y_t)):
        groups = [y[~reg], y[reg]]                       # [unregistered, registered]
        means.append(sum(wi * g.mean() for wi, g in zip(w, groups)))
        vars.append(sum(wi**2 * g.var(ddof=1) / g.size for wi, g in zip(w, groups)))
    t = (means[1] - means[0]) / np.sqrt(vars[0] + vars[1])
    return 2 * tdist.sf(abs(t), y_c.size + y_t.size - 2)

Validate with Monte Carlo as always: generate A/A worlds (no effect → we should see FPR \(\approx \alpha\)) and A/B worlds (effect +10 UAH → power), for the plain and stratified tests on the same data.

(3) “We didn’t grow the sample — we stopped paying variance for what we already knew about customers: registered users spend more. Removing that known spread let the test see the effect.”

2 Part II — CUPED

Case. Stratification used a coarse label. But we have something far richer — each user’s own history: how much they spent before the experiment (pre). Use it to compare every user with their own past.

CUPED (Controlled-experiment Using Pre-Experiment Data) adjusts the metric \(Y\) with a pre-experiment covariate \(X\):

\[ Y_{cuped} = Y - \theta X, \qquad \theta = \frac{\operatorname{Cov}(X, Y)}{\operatorname{Var}(X)}, \qquad \operatorname{Var}(Y_{cuped}) = \operatorname{Var}(Y)\,(1 - r^2). \]

\(\theta\) is a constant shared by both arms, so thanks to randomization the difference of means stays unbiased: we don’t move the effect estimate, we only remove its predictable noise.

Tip🔮 Guess first

CUPED’s gain is exactly \(1 - r^2\). In our world pre correlates with arpu at \(0.7\) within a stratum. But pre also “knows” the stratum (registered users are higher on both pre and arpu). Will the overall correlation of pre with arpu be exactly \(0.7\) or higher? And what variance ratio follows?

2.1 Tool v2: calculate_theta + cuped

def calculate_theta(x, y):
    return np.cov(x, y)[0, 1] / x.var(ddof=1)

def cuped(y, x, theta):
    return y - theta * x
rng = np.random.default_rng(0)
a = greenbowl_users(200_000, rng)                    # big cohort to estimate r
r_full = np.corrcoef(a["pre"], a["arpu"])[0, 1]
theta  = calculate_theta(a["pre"], a["arpu"])
vr     = cuped(a["arpu"], a["pre"], theta).var() / a["arpu"].var()
print(f"overall corr r(pre, arpu): {r_full:.3f}")
print(f"1 - r^2:                   {1 - r_full**2:.3f}")
print(f"measured variance ratio:   {vr:.3f}")
overall corr r(pre, arpu): 0.818
1 - r^2:                   0.331
measured variance ratio:   0.331

The correlation turned out \(\approx 0.82\), not \(0.7\): pre carries both the within-stratum history and the stratum itself. So CUPED alone shaves \(\approx 67\%\) of the variance — more than stratification. Remember this fact: in Section 4 it explains why “stratification + CUPED” barely adds anything over CUPED alone.

rng, MC = np.random.default_rng(5), 400

                                    cuped(t_["arpu"], t_["pre"], th2), equal_var=False).pvalue < alpha

NoteSolution 2 
def make_cov(y, r, rng):
    """A covariate with a given OVERALL correlation r to y."""
    zy = (y - y.mean()) / y.std()
    return r * zy + np.sqrt(1 - r**2) * rng.standard_normal(y.size)

rng_c = np.random.default_rng(3)
a = greenbowl_users(200_000, rng_c)
for r in (0.2, 0.5, 0.7):
    x = make_cov(a["arpu"], r, rng_c)
    th = calculate_theta(x, a["arpu"])
    ratio = cuped(a["arpu"], x, th).var() / a["arpu"].var()
    print(f"(1) r = {r}: variance ratio {ratio:.3f}  (1 - r^2 = {1 - r**2:.2f})")
(1) r = 0.2: variance ratio 0.959  (1 - r^2 = 0.96)
(1) r = 0.5: variance ratio 0.752  (1 - r^2 = 0.75)
(1) r = 0.7: variance ratio 0.510  (1 - r^2 = 0.51)

Interpretation. (1) The law holds exactly: \(r=0.2 \to 0.96\) (only 4% shaved — not worth a pipeline), \(r=0.5 \to 0.75\), \(r=0.7 \to 0.51\). The sanity floor is \(|r| \gtrsim 0.3\). (2) For new users substitute \(X = \bar X\) (the covariate mean): then \(Y_{cuped} = Y - \theta \bar X\) — they simply get no adjustment, and unbiasedness holds because the constant is the same in both arms. At Netflix new users give 5–15% variance reduction vs 40% for existing ones, precisely due to missing history.

ImportantCareful: the covariate must be pre-treatment

CUPED and stratification are safe only on pre-experiment features. A covariate measured during the experiment (sessions, visits) can absorb part of the effect — and silently bias the estimate. Simple rule: anything fixed before launch is fine; anything the treatment could move is not.

3 Part III — Ratio metrics and linearization

Case. The PM asks for a different metric: session→order conversion — “of all sessions, how many ended with a purchase?”. The temptation: unroll every session into \(0/1\) and compare two proportions with a z-test. But we randomized users, while we count over sessions.

WarningCatch the error 🕵️

GreenBowl ran an A/A conversion test (no effect). Two analysts argue about how to compute it.

def pooled_session_pvalue(sessions_c, orders_c, sessions_t, orders_t):
    """t-test on unrolled 0/1 outcomes over SESSIONS (Analyst A's analysis)."""
    out = []
    for sess, ordr in ((sessions_c, orders_c), (sessions_t, orders_t)):
        ns, k = sess.sum(), ordr.sum()
        mean  = k / ns
        var   = (k*(1 - mean)**2 + (ns - k)*mean**2) / (ns - 1)
        out.append((mean, var, ns))
    (m1, v1, n1), (m2, v2, n2) = out
    t = (m2 - m1) / np.sqrt(v1/n1 + v2/n2)
    return 2 * tdist.sf(abs(t), n1 + n2 - 2)

rng, MC_r = np.random.default_rng(7), 300
fpr_pool = 0
for _ in range(MC_r):
    a = greenbowl_users(2000, rng)
    b = greenbowl_users(2000, rng)
    fpr_pool += pooled_session_pvalue(a["sessions"], a["orders"],
                                      b["sessions"], b["orders"]) < alpha
print(f"A/A FPR (pooled sessions): {wilson(fpr_pool, MC_r)}")
A/A FPR (pooled sessions): 0.457  Wilson (0.401, 0.513)

Analyst A: “Tens of thousands of sessions, tiny standard errors — take a z-test of proportions and let big \(n\) do its thing.”

Analyst B: “Sessions of one user are not i.i.d.: each has their own propensity to buy. The effective unit is the user, not the session. Look: on a clean A/A the pooled test rejects the null in half the cases — a machine for shipping placebo features.”

Who is right? Analyst B: FPR \(\approx 0.5\) instead of \(0.05\). Sessions multiply the volume of data, not the evidence — the unit of analysis must equal the unit of randomization.

The honest per-arm metric is the ratio \(K = \sum \text{orders} / \sum \text{sessions}\) (users stay whole). In the lecture we built its CI with a user-level bootstrap; today — faster algebra, linearization: turn each pair \((O_i, M_i)\) into a single per-user number \(Z_i\) to which a plain t-test applies.

3.1 Tool v3: linearize

\[ Z_i = K + \frac{1}{\overline{O}}\big(M_i - K\,O_i\big), \qquad K = \frac{\overline{M}}{\overline{O}} \]

def linearize(num, den):
    """Per-user linearized ratio metric (delta method).

    num = orders (numerator), den = sessions (denominator).
    """
    k = num.sum() / den.sum()
    return k + (num - k * den) / den.mean()
rng = np.random.default_rng(1)
a = greenbowl_users(5000, rng)
z = linearize(a["orders"], a["sessions"])
print(f"K       = {a['orders'].sum()/a['sessions'].sum():.5f}")
print(f"mean(Z) = {z.mean():.5f}   <- reproduces K exactly")
K       = 0.19992
mean(Z) = 0.19992   <- reproduces K exactly

mean(Z) equals \(K\) exactly, so the t-test on \(Z\) compares precisely the quantity the PM asks about. Check honesty and power:

rng, MC_r = np.random.default_rng(7), 300
fpr_lin = agree = 0

    b = greenbowl_users(2000, rng)

The linearized t-test’s FPR sits on \(\alpha\) — unlike Analyst A’s pooled test. And it costs one line of algebra instead of thousands of bootstrap resamples: on a platform running thousands of metrics nightly, that is the difference between hours and seconds.

4 Part IV — Everything composes + Monte Carlo

The linearized \(Z\), stratification and CUPED are all operations on a per-user column, so they stack. Let’s combine CUPED + stratification into one criterion vr_ci returning a variance-reduced CI for the ARPU difference.

def vr_ci(control, test, stratum_c=None, stratum_t=None,
          cov_c=None, cov_t=None, alpha=0.05):
    """Variance-reduced CI for the difference of means test - control.

    First CUPED (if a covariate is given), then a stratified/plain mean.
    Returns (diff, (lo, hi), se).
    """
    yc, yt = np.asarray(control, float), np.asarray(test, float)
    if cov_c is not None:                                    # CUPED step
        th = calculate_theta(np.r_[cov_c, cov_t], np.r_[yc, yt])
        yc, yt = yc - th*cov_c, yt - th*cov_t

    def mean_var(reg, y):
        if reg is None:
            return y.mean(), y.var(ddof=1) / y.size
        w, g = (0.5, 0.5), [y[~reg], y[reg]]                 # stratification step
        m = sum(wi*x.mean() for wi, x in zip(w, g))
        v = sum(wi**2 * x.var(ddof=1)/x.size for wi, x in zip(w, g))
        return m, v

    mc, vc = mean_var(stratum_c, yc)
    mt, vt = mean_var(stratum_t, yt)
    diff, se = mt - mc, np.sqrt(vc + vt)
    z = norm.ppf(1 - alpha/2)
    return diff, (diff - z*se, diff + z*se), se
Tip🔮 Guess first

The power order is clear: plain < strat < cuped. But strat + CUPED — markedly better than CUPED alone, or nearly the same?

def strat_cuped_p(sc, xc, yc, st, xt, yt):
    th = calculate_theta(np.r_[xc, xt], np.r_[yc, yt])
    return strat_ttest(sc, yc - th*xc, st, yt - th*xt)

    cnt["cuped"] += ttest_ind(cuped(a["arpu"], a["pre"], th),
                              cuped(t_["arpu"], t_["pre"], th), equal_var=False).pvalue < alpha
    cnt["strat+cuped"] += strat_cuped_p(a["stratum"], a["pre"], a["arpu"],
                                        t_["stratum"], t_["pre"], t_["arpu"]) < alpha

5 Part V — Finale: vr_report

Case. The Kyiv email-campaign A/B is done: 1005 users per arm. The promo-bundle subsidy costs 6 UAH per user — that’s the breakeven: the feature pays off only if it lifts ARPU by more than 6 UAH. The CFO awaits a decision.

BASE, PERIODS = 80_000, 26              # Kyiv base; 2-week periods per year

def vr_report(control, test, breakeven, stratum_c=None, stratum_t=None,
              cov_c=None, cov_t=None, base=BASE, periods=PERIODS):
    """Final report: variance-reduced effect, three-zone decision, P(pays off), EV."""
    diff, (lo, hi), se = vr_ci(control, test, stratum_c, stratum_t, cov_c, cov_t)
    zone = ("SHIP"                   if lo > breakeven else
            "KILL"                   if hi < breakeven else
            "GREY ZONE — need data")
    p_be = norm.sf((breakeven - diff) / se)          # P(effect >= breakeven)
    ev   = base * periods * (diff - breakeven)        # expected net value per year
    print(f"ARPU effect: {diff:+.2f} UAH   95% CI ({lo:+.2f}, {hi:+.2f})")
    print(f"effective SE: {se:.2f} UAH   breakeven {breakeven:+.0f} UAH")
    print(f"decision:    {zone}")
    print(f"P(pays off): {p_be:.0%}")
    print(f"EV per year: {ev/1e6:+.1f}M UAH")
    return {"diff": diff, "ci": (lo, hi), "zone": zone, "p": p_be, "ev": ev}

Pitfalls + checklist

Pitfall Why it hurts What to do
Stratify / CUPED on a treatment-affected feature the covariate absorbs the effect → biased estimate pre-treatment features only
Pool sessions into 0/1 and z-test proportions one user’s sessions aren’t i.i.d. → FPR ≫ α unit of analysis = unit of randomization; linearize
Read the ratio without the denominator the treatment moves \(\sum O\) too test the denominator separately with a t-test
Compare the CI to zero when the feature costs money “significant” ≠ “pays off” decision threshold is breakeven, three zones
Require “lower bound > design-MDE” systematic false negatives on paying features MDE sizes \(n\), breakeven decides
“Power at the observed effect” a deterministic function of the \(p\)-value power is computed before the experiment
Trust an engine because “the code looks right” a small change can break calibration A/A Monte-Carlo bench: FPR ≈ α
