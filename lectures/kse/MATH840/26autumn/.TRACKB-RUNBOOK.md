# Track B — операційний порядок

Що робити з челенджами від видачі рядів до виставлення балів. Стосується тижнів 4, 6, 7, 8, 9 —
щоразу той самий ряд у того самого студента, тож усе нижче повторюється п'ять разів.

## Одноразово, уже зроблено

- Пул зібрано: `python trackb_pool.py --jobs 16` → `data/trackb/` (публічні ряди) і
  `grading/trackb_pool.json` (**ключ**: прихований горизонт, справжні назви, еталонні скори).
- `grading/` у `.gitignore`. Це має лишитися так до кінця курсу: у файлі лежать відповіді на п'ять
  челенджів.
- Ряди в `data/trackb/` запушені в GitHub — саме звідти їх тягнуть шаблон і демо.

**Пул не перебудовувати.** Видача детермінована, тож повторний запуск дасть ті самі коди й ті самі
дані, але будь-яка зміна параметрів (смуга, варіанти, `MAX_SERVED`) змінить ряди під студентами
посеред курсу.

## Перед заняттям

1. Перевірити, що ряди доступні публічно:

   ```bash
   curl -s -o /dev/null -w "%{http_code}\n" \
     https://raw.githubusercontent.com/Aranaur/aranaur.rbind.io/main/lectures/kse/MATH840/26autumn/data/trackb/index.csv
   ```

2. Активність у Moodle: дедлайн **23:59 того ж дня**, прикріплений `labs/.labNN.pdf`, посилання на
   шаблон у Colab. Три файли на здачу: `*_forecast.csv`, `*.pdf`, `*.ipynb`.

## На занятті

Нічого не збираємо. Останній блок практики — видача ряду: усі запускають клітинку з власним
ідентифікатором і бачать свій код. Хто забув ідентифікатор — він є в стовпці `student_id` їхніх
попередніх здач.

## Наступного ранку: скоринг

1. Завантажити з Moodle **лише** файли прогнозів у `grading/submissions/chN/`. PDF і ноутбуки —
   окремо, вони йдуть на оцінювання рубрики, а не в скорер.

2. Порахувати:

   ```bash
   cd lectures/kse/MATH840/26autumn/infra
   python trackb_score.py ../grading/submissions/ch1 --out ../grading/ch1_scores.csv
   ```

   Скорер друкує по рядку на здачу: MASE студента, MASE його бенчмарка, `skill`, бали 3/2/1 і
   покриття 80% інтервалу. Бенчмарк перераховується з **публічних** даних тим самим правилом, що в
   шаблоні, тож студент може відтворити все, крім майбутнього.

3. Подивитися на рядки з `points=0` — це зламаний формат, не погана модель. У нотатці написано, що
   саме не так (дати, кількість рядків, `NaN`). За правилами хендаута точність тоді 0, бо прогнозу
   фактично немає; розділи 1, 3 і 4 оцінюються як звичайно. Варто написати такому студенту, що
   клітинка перевірки формату в шаблоні ловить це за секунду.

4. Перевірити блок «same series drawn by more than one student». Двоє на одному коді — нормально:
   видача хешем, а не розподілом. Ненормально — **однакові числа**: порівняйте перші `yhat`. Різні
   моделі на одному ряді збігатися до третього знака не можуть.

5. Опублікувати скор. Показуємо студентові: його `skill`, його бали за точність, MASE його бенчмарка.
   **Не показуємо** чужі результати, чужі ряди й позицію в групі — ряди різні, порівнювати нема з чим.

## Оцінювання рубрики

Точність (3 бали) уже стоїть. Решта 5 — розділи 1, 3 і 4, промпт у `grading/ch1_prompt.md`.
Платформі віддаємо на кожного студента:

- `SURNAME_chN.pdf` і `SURNAME_chN.ipynb`;
- завдання: `labs/.labNN.pdf`;
- промпт: `grading/ch1_prompt.md`;
- рядок скору з кроку 2 у такому вигляді:

  ```
  code=TS-XXXXX  benchmark=snaive  mase=0.812  benchmark_mase=0.905  skill=0.897  points=3
  ```

Промпт прямо сказано: ці 3 бали не перераховувати й не вгадувати, а використати у фідбеку.

## Якщо щось пішло не так

| Ситуація | Що робити |
|---|---|
| Студент каже, що його ряд «неможливо прогнозувати» | Подивіться `skill` еталонної моделі в `trackb_pool.json`: він у смузі 0,70–0,90, інакше ряд не видавався б |
| Студент прогнозував не той горизонт | Скорер відхилить файл; `h` є і в `index.csv`, і в шаблоні |
| Здача без файлу прогнозу | Точність 0, решта розділів оцінюється; у фідбеку сказати, що файл пише остання клітинка |
| Двоє студентів із однаковим кодом і схожими числами | Порівняти ноутбуки; це питання доброчесності, а не скорингу |
| Ряд зник із `data/trackb/` | Не перезбирати пул: відновити файл з git (`git checkout -- data/trackb/TS-XXXXX.csv`) |
