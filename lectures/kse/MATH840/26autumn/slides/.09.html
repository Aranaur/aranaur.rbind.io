Where this fits

Eight weeks of local models

Every model so far has been local: fitted to one series, with its own parameters, knowing nothing about any other series.

Three ways a network enters forecasting

1. NNAR — a non-linear AR

The same lags as an AR model, but the forecast is a non-linear function of them. Still local: one series, its own weights.

2. NeuralProphet — Prophet with lags

Week 8’s trend, seasons and events, plus an autoregressive network — the error dynamics Prophet was missing.

3. Global networks

One model trained on many series at once: LightGBM on lags, then the neuralforecast zoo — MLP, LSTM, TCN, DeepAR, N-BEATS, N-HiTS, TFT, PatchTST, TiDE.

The question for each is the one we have asked for eight weeks: does it beat the benchmark on a holdout it never saw? Next lecture takes the last step — pretrained models that forecast your series without being trained on it at all.

Neural network autoregression

An AR model is a network with no hidden layer

\[ \hat y_t = c + \phi_1 y_{t-1} + \phi_2 y_{t-2} + \phi_3 y_{t-3} \]

Time series Neural networks
lags \(y_{t-i}\) inputs
coefficients \(\phi_i\) weights
intercept \(c\) bias
least squares training on squared loss

A linear regression on lags is a neural network — one with no hidden layer and no activation.

Add a hidden layer

Each hidden neuron takes its own weighted sum of the lags and squeezes it through a non-linear activation:

\[ \begin{aligned} z_j &= b_j + \sum_{i=1}^{p} w_{ij}\, y_{t-i}\\[2pt] h_j &= s(z_j) = \frac{1}{1 + e^{-z_j}}\\[2pt] \hat y_t &= a + \sum_{j=1}^{k} v_j\, h_j \end{aligned} \]

Code 
fig, ax = plt.subplots(figsize=(6, 3.6))
draw_net(ax, [3, 4, 1], [["$y_{t-1}$", "$y_{t-2}$", "$y_{t-3}$"], ["$h_1$", "$h_2$", "$h_3$", "$h_4$"],
                         [r"$\hat y_t$"]],
         [blue, turquoise, red_pink], "NNAR(3, 4): one hidden layer")
plt.show()

\(k\) hidden neurons, each a different “view” of the lags. The sigmoid is what makes the model non-linear — without it the network collapses back to an AR model. Weights start at random values and are fitted by gradient descent on the squared error.

NNAR\((p, P, k)_m\)

The model in FPP3 §12.4 — nnetar() in R — is exactly this network, with conventions that make it a forecasting method:

  • Inputs: \(p\) ordinary lags \(y_{t-1}, \dots, y_{t-p}\) and \(P\) seasonal lags \(y_{t-m}, \dots, y_{t-Pm}\).
  • Hidden layer: one, with \(k\) neurons. Default \(k = (p + P + 1)/2\), rounded.
  • Defaults for \(p\): the order of the best AR model on the seasonally adjusted series; \(P = 1\).
  • Twenty networks, each from different random starting weights, and their forecasts averaged — a combination (Week 8) used to tame the randomness of training.
  • Inputs are scaled first; a network trains badly on raw values in the thousands.

NNAR\((p, 0, k)\) is the non-seasonal version — the one we fit next.

Fitting NNAR(9, 5) by hand

y_ss = np.sqrt(spots["SUNACTIVITY"].to_numpy())    # square root keeps the forecasts positive
H_SS = 30
train_ss, test_ss = y_ss[:-H_SS], y_ss[-H_SS:]
p, k = 9, 5
mu, sd = train_ss.mean(), train_ss.std()
z = (train_ss - mu) / sd                            # scale the inputs


def lag_matrix(z, p):
    X = np.column_stack([z[p - i - 1:len(z) - i - 1] for i in range(p)])   # y_{t-1}, ..., y_{t-p}
    return X, z[p:]


X, target = lag_matrix(z, p)
nets = [MLPRegressor(hidden_layer_sizes=(k,), activation="logistic", alpha=1e-3,
                     max_iter=5000, random_state=seed).fit(X, target)
        for seed in range(20)]                                             # twenty networks
print(f"{len(target)} training rows, {p} inputs, {k} hidden neurons, "
      f"{p * k + k + k + 1} weights per network")
270 training rows, 9 inputs, 5 hidden neurons, 56 weights per network

Forecasting: one step at a time

A network predicts one step ahead. For \(h > 1\) the forecast is fed back as if it were data — the same recursion as ARIMA, but through a non-linear function:

def nnar_forecast(nets, z, h, noise=None, rng=None):
    history, out = list(z[-p:]), []
    for _ in range(h):
        x = np.array(history[::-1][:p])[None, :]               # the latest p values, newest first
        value = np.mean([net.predict(x)[0] for net in nets])   # average of the twenty networks
        if noise is not None:
            value += rng.choice(noise)                         # a resampled training error
        out.append(value)
        history.append(value)
    return np.array(out)


point_ss = (nnar_forecast(nets, z, H_SS) * sd + mu) ** 2      # back to the sunspot scale

There is no formula for the forecast variance of a non-linear model. FPP’s answer: simulate. Add a resampled training error at every step, repeat many times, and read the interval off the paths.

What NNAR is, and is not

  • Is: an autoregression that can bend. When the dynamics are genuinely non-linear — asymmetric cycles, thresholds, saturation — it can see what a linear model cannot.
  • Is not: interpretable. 56 weights per network, twenty networks; there is no \(\phi_1\) to read.
  • Is not: stable without care. Different seeds give different networks; that is why it averages twenty.
  • Is not: data-efficient. Sunspots give 300 years; your Track B series gives 56 to 264 observations, and a network with 56 weights per 100 points is fitting noise.

That last point is the real limit of a local network — and the reason the last part of this lecture trains on many series at once.

From Prophet to NeuralProphet

What Prophet was missing

Week 8’s verdict on Prophet: a convenient regression — piecewise trend, Fourier seasons, holiday windows — with no error dynamics. It never looks at yesterday. Its intervals were too narrow, and on cement and electricity it lost to seasonal naive.

NeuralProphet (Triebe et al., 2021) keeps Prophet’s decomposition and adds what was missing:

\[ \hat y_t = \underbrace{T(t) + S(t) + E(t) + F(t)}_{\text{Prophet's terms}} \; + \; \underbrace{A(t)}_{\text{AR-Net}} \; + \; \underbrace{L(t)}_{\text{lagged regressors}} \]

  • \(T, S, E, F\): trend, Fourier seasonality, events, future regressors — as in Prophet.
  • \(A(t)\): an autoregression on the last \(p\) values, fitted as a small network — AR-Net. With no hidden layer it is a linear AR(\(p\)); with hidden layers it is NNAR.
  • \(L(t)\): lags of other series — Week 7’s lagged predictors.
  • Everything is fitted together in PyTorch, by stochastic gradient descent, not by Stan.

The same interface

from neuralprophet import NeuralProphet

m = NeuralProphet(n_lags=14,          # AR-Net: the last 14 days as inputs
                  n_forecasts=7)      # one output per step: 7 days ahead, directly
m = m.add_future_regressor("tournament")
m.fit(train[["ds", "y", "tournament"]], freq="D")
forecast = m.predict(test[["ds", "y", "tournament"]])   # yhat1 ... yhat7
  • n_forecasts=7 makes the forecast direct: one output neuron per horizon, not a recursion as in NNAR. Column yhat3 is the forecast made three days earlier.
  • Without n_lags the model is Prophet refitted by gradient descent — a useful check that nothing else has changed.

What the lags bought

  • Prophet and NeuralProphet without lags lose to seasonal naive at every horizon: on daily attention data, “same day last week” knows more than any smooth trend and season. Refitting Prophet by gradient descent helps a little, not enough — the missing piece was never the optimiser.
  • The AR-Net closes most of that gap. Its error at 7 days is less than two thirds of Prophet’s.
  • One day ahead it is no better than naive. “Same as yesterday” is very hard to beat at \(h = 1\); the AR-Net’s advantage grows with the horizon, to about 12% at \(h = 7\).

With no hidden layer the AR-Net is a \(7 \times 14\) matrix: one row of lag weights per horizon.

The largest weights are on lag 14 — the same weekday two weeks back — and the signs alternate from lag to lag. This is not an ARIMA \(\phi\) you can read: correlated lags share the work in arbitrary ways. NeuralProphet buys accuracy here, not a cleaner story.

Global models

Local and global

Local — one model per series

  • \(N\) series → \(N\) sets of parameters.
  • Each set is estimated from one series.
  • ETS, ARIMA, NNAR, Prophet.

Global — one model for all

  • \(N\) series → one set of parameters.
  • Estimated from every window of every series.
  • A seasonal shape seen in 500 series helps forecast the 501st.

A global model needs the series to be comparable, so each one is scaled by its own level first. After that, it learns “what happens after a pattern like this”, pooled over everything it has seen.

Evidence from the competitions: in M4 (2018) the winner was a hybrid — exponential smoothing inside a recurrent network trained across series — and the pure machine-learning entries did worse than the statistical benchmarks. In M5 (2020), on tens of thousands of Walmart series, the top of the leaderboard was dominated by LightGBM trained globally.

A global LightGBM on lags

The M5 recipe: a gradient-boosted tree model, one for all 1428 series, on lag features. Week 7’s dynamic regression with the lags as predictors — except that a tree finds the non-linearities itself.

from mlforecast import MLForecast
from mlforecast.target_transforms import Differences, LocalStandardScaler
import lightgbm as lgb

boosted = MLForecast(
    models={"LightGBM": lgb.LGBMRegressor(n_estimators=300, learning_rate=0.05, verbose=-1)},
    freq="MS",
    lags=[1, 2, 3, 6, 12, 24],                                   # the features
    date_features=["month"],
    target_transforms=[Differences([12]), LocalStandardScaler()],   # D = 1, then each series scaled
)
boosted.fit(train_m3)
forecasts = forecasts.merge(boosted.predict(H_M3), on=["unique_id", "ds"])
  • Differences([12]) is Week 7’s seasonal difference; LocalStandardScaler puts every series on one scale, which is what makes pooling them possible.
  • Forecasts are recursive, as for NNAR: each prediction becomes a lag for the next.

One reasonable configuration, the kind you would try first — not tuned. Tuning a global model is a project of its own; the next slides show what you get on the first attempt.

The neuralforecast model zoo

How neuralforecast trains every model

Every model in neuralforecast learns from the same kind of example: a window of input_size past values and the h values that follow, cut at a random point of a random series.

Code

    ax.plot(example, color="lightgray", linewidth=1)

            label="target: the next 18")

axes[0].legend(loc="upper left", fontsize=8)
fig.suptitle("Three training examples from one series; a batch mixes windows from many series", fontsize=11)
plt.show()
  • Scaling (scaler_type): each window is scaled by its own level and spread, so a series in the millions and a series in the tens can share one set of weights.
  • Loss (loss): MAE by default; a distribution or quantile loss gives intervals.
  • Training (max_steps): that many batches of windows, by gradient descent. Forecasting is one forward pass on the last window of each series.

Four families

Family Models How it reads the window
Fully connected MLP, N-BEATS, N-HiTS, TiDE all 24 values at once, as one input vector
Recurrent RNN, LSTM, GRU, DeepAR one value at a time, carrying a state forward
Convolutional TCN sliding filters over neighbouring values
Attention TFT, PatchTST every position weighs every other

The simplest is the MLP: the window goes in as a vector, through hidden layers with ReLU, and all 18 forecasts come out at once — a direct forecast, not NNAR’s recursion:

\[ \hat{\mathbf{y}}_{T+1:T+h} = W_2\, \text{ReLU}\!\left(W_1\, \mathbf{y}_{T-23:T} + b_1\right) + b_2 \]

NNAR from the first section, made global and multi-output. Every other model in this section is a more careful way of turning the window into those \(h\) numbers.

Recurrent networks: a memory that is carried forward

NNAR sees a fixed window of \(p\) lags. A recurrent network (RNN) reads the series one value at a time and carries a hidden state \(h_t\) — a vector summary of everything so far:

\[ h_t = \tanh\left(W h_{t-1} + U y_t + b\right), \qquad \hat y_{t+1} = V h_t + c \]

No fixed window, and the same weights at every step — as ARIMA’s recursion is to a regression on fixed lags.

TCN: convolutions that only look back

A temporal convolutional network (Bai, Kolter & Koltun, 2018) slides small filters along the series — Week 2’s moving average, with learned weights and a non-linearity, stacked in layers.

Code 
fig, ax = plt.subplots(figsize=(12, 3))
n, dilations = 16, [1, 2, 4]                  # layer l+1 combines t and t - dilations[l] of layer l
reach = {3: {15}}
for layer in (2, 1, 0):
    reach[layer] = {s for t in reach[layer + 1] for s in (t, t - dilations[layer])}
for layer in range(4):
    ax.scatter(range(n), [layer] * n, s=40, color="white", edgecolor=slate, zorder=3)
    ax.scatter(sorted(reach[layer]), [layer] * len(reach[layer]), s=60, color=red_pink, zorder=4)
for layer, d in enumerate(dilations):
    for t in range(d, n):
        on_path = t in reach[layer + 1]
        for src in (t, t - d):
            ax.plot([src, t], [layer, layer + 1], color=red_pink if on_path else "lightgray",
                    linewidth=1.4 if on_path else 0.6, zorder=2 if on_path else 1)
ax.set_yticks(range(4), ["input", "dilation 1", "dilation 2", "dilation 4 → output"])
ax.set_xticks([])
ax.set_title("Each output sees only the past (causal), and the reach doubles with every layer (dilated)")
plt.show()
  • Causal: the filter at time \(t\) uses only \(t, t-1, \dots\) — never the future.
  • Dilated: layer \(\ell\) skips \(2^{\ell}\) steps, so a few layers cover a long window — here three layers reach eight months back.
  • No recurrence, so every position is computed in parallel: faster to train than an LSTM.

DeepAR: a distribution at every step

DeepAR (Salinas et al., 2020; Amazon) is a global LSTM whose output is not a number but the parameters of a distribution — here a Student-\(t\), \((\mu_t, \sigma_t, \nu_t)\):

\[ y_t \mid y_{1:t-1} \sim t_{\nu_t}\!\left(\mu_t, \sigma_t\right), \qquad (\mu_t, \sigma_t, \nu_t) = g(h_t) \]

  • Training maximises the likelihood of the observed values — Week 4’s maximum likelihood, with an LSTM in place of the ETS equations.
  • Forecasting samples: draw \(y_{T+1}\), feed it back, draw \(y_{T+2}\), … Many sample paths give the quantiles — the NNAR simulation from the first section, built into the model.
  • The interval comes from the model, not from resampled residuals — so it can widen where the network has learned that series are volatile.

N-BEATS: pass on what you cannot explain

N-BEATS (Oreshkin et al., 2020): a chain of fully connected blocks. Two of them, on Air Passengers:

Code 
window = np.log(air["y"].to_numpy()[-72:-24])           # 48 months in, 24 ahead
future = np.log(air["y"].to_numpy()[-24:])
t = np.arange(72) / 72                                     # one time axis for backcast and forecast
past, ahead = slice(0, 48), slice(48, 72)
trend_basis = np.column_stack([t ** k for k in range(2)])  # 1, t
season_basis = np.column_stack([f(2 * np.pi * k * np.arange(72) / 12) for k in (1, 2) for f in (np.cos, np.sin)])


def block(x, basis):
    theta = np.linalg.lstsq(basis[past], x, rcond=None)[0]   # the network learns theta; here, least squares
    return basis[past] @ theta, basis[ahead] @ theta         # backcast, forecast


trend_back, trend_fore = block(window, trend_basis)
rest = window - trend_back
season_back, season_fore = block(rest, season_basis)
left = rest - season_back

months, horizon = np.arange(48), np.arange(48, 72)
fig, axes = plt.subplots(1, 3, figsize=(13.5, 3.7), width_ratios=[1.15, 1.15, 1.15])
axes[0].plot(months, window, color=slate, linewidth=1.2, label="input: the window")
axes[0].plot(months, trend_back, color=blue, linewidth=2, label="backcast")
axes[0].plot(horizon, trend_fore, "--", color=blue, linewidth=2, label="forecast")
axes[0].set_title("Block 1 (trend): explains what it can", fontsize=10, color=blue)
axes[1].plot(months, rest, color=slate, linewidth=1.2, label="input: window − block 1's backcast")
axes[1].plot(months, season_back, color=orange, linewidth=2, label="backcast")
axes[1].plot(horizon, season_fore, "--", color=orange, linewidth=2, label="forecast")
axes[1].plot(months, left, ":", color="grey", linewidth=1, label="still unexplained")
axes[1].set_title("Block 2 (season): gets only the rest", fontsize=10, color=orange)
axes[2].plot(months, window, color=slate, linewidth=1.2, label="window")
axes[2].plot(horizon, future, color="black", linewidth=1.2, label="actual")
axes[2].plot(horizon, trend_fore + season_fore, color=red_pink, linewidth=2.2, label="block 1 + block 2")
axes[2].set_title("Forecast = sum of the blocks' forecasts", fontsize=10, color=red_pink)
for ax in axes:
    ax.axvline(47.5, color="grey", linewidth=0.8)
    ax.set_xlabel("month")
    ax.legend(fontsize=7.5, loc="best")
axes[0].set_ylabel("log passengers")
for x in (0.345, 0.66):
    fig.text(x, 0.5, "→", fontsize=24, color="grey", ha="center", va="center")
plt.show()
  • Each block returns a backcast (the part of its input it explains) and a forecast of that part, then passes on the rest. The final forecast is the sum of the blocks’ forecasts.
  • Real N-BEATS stacks dozens of blocks whose layers learn the coefficients (least squares here, for the mechanics). Interpretable blocks are fixed to trend and Fourier terms (Week 5). It beat M4’s winner.

The same 1428 series, horizon and windows as LightGBM. Every model with one configuration, its library defaults plus three shared settings — nothing tuned:

What the table says

  • No network, untuned, beats ETS and Theta on M3. The best three — N-BEATS, N-HiTS and the plain MLP — are level with ETS. The fully connected family wins the zoo.
  • Architecture fame is not accuracy. PatchTST and TiDE, built for long multivariate data, are the two worst networks here; the LSTM loses to the plain MLP.
  • Cost differs. On a GPU, TFT trains for 18 seconds where the MLP takes 4; on a laptop CPU the same gap is ten minutes against ten seconds — for a middling score.
  • The Week 8 average of ETS and Theta is still the best forecast on the board, and it took no GPU, no seed and no hyperparameters.

M3 is home ground for local models: short series (median 115 months) from unrelated domains — little for pooling to borrow. Global networks win where series are many, long and alike — M5’s products from one retailer, electricity meters, web traffic — and where someone tunes them.

Tuning, and why we did not

Every model above has a dozen hyperparameters: input_size, layer sizes, learning rate, max_steps, dropout. neuralforecast ships an Auto version of each that searches them on validation windows:

from neuralforecast.auto import AutoNHITS

auto = NeuralForecast(models=[AutoNHITS(h=18, backend="optuna", num_samples=20)], freq="MS")
auto.fit(train_m3, val_size=18)        # 20 configurations, each judged on the last 18 months
  • Twenty configurations cost twenty trainings. On a laptop CPU that is the difference between a minute and an evening.
  • The validation window must not be the test window — Week 3’s rule, now with twenty chances to break it.
  • Tuning is worth it when the series are many and alike, and the forecasts are used every day. For one series, Weeks 4–8 are cheaper and usually as good.

Wrapping up

Eight ways to get this wrong

Trap What you see Fix
A neural network on 100 observations A perfect fit, a wild forecast Few weights, a global model, or a simpler model
One random seed A different forecast every run Average several networks, or fix and report the seed
Unscaled inputs to a network Training that never converges Scale each series first
A global model on incomparable series Big series dominate the loss Scale per series: LocalStandardScaler, scaler_type
Neural results without a benchmark “LSTM: MAE 412” — and nothing to compare it with Seasonal naive and ETS on the same holdout, always
A daily model with no lags Loses to “same day last week” Add the lags: AR-Net, or a model that has them
Tuning on the test window A score that will not repeat Validation windows before the test, as in Week 3
“Deep” read as “better” A slow, opaque model that loses to Theta It is one more candidate on the rolling origin

What this lecture is, in one slide

  • NNAR is an autoregression with a hidden layer: non-linear, local, averaged over random starts, with intervals by simulation. It needs long series.
  • NeuralProphet is Prophet plus an AR-Net. On daily data the lags, not the decomposition, carry the accuracy — and the package itself is no longer maintained.
  • Global models pool many series after scaling each. Every neuralforecast model learns from the same windows; they differ in how they read one — all at once (MLP, N-BEATS, N-HiTS, TiDE), step by step (LSTM, DeepAR), by filters (TCN) or by attention (TFT, PatchTST).
  • On M3 none of them, untuned, clearly beats ETS and Theta. Networks earn their cost where series are many, long and alike — and where someone tunes them.
